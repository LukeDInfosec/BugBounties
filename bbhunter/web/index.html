Programme

Scope is the safety boundary, not a filter. Every tool's traffic is routed through a local gate that re-checks these rules on every single connection, so a crawler following a redirect off-scope is refused at the socket rather than discovered afterwards.

Set a handle and every request will carry X-Bug-Bounty: <handle>. Most programmes ask for this; it is what lets a blue team tell your testing from an attack.

The chain

Each step feeds the next. Run the lot with one button, or run a single step when you have changed something and only need that part redone.

Active testing — off by default
These stages send payloads. They are scope-locked and rate-limited like everything else, and they only ever look for read-only proof — a reflection, a boolean difference, an out-of-band callback. Nothing here writes, deletes or sends mail. They still generate traffic a target will notice, so turn them on deliberately.

What changed since the last run

Being first to a newly exposed asset is where most of the value in monitoring a programme is. A stage that failed can never produce "disappeared" here — that would train you to ignore this screen.

Tooling

The framework works with whatever is present and says so when something is missing, rather than failing halfway through a run. Required tools are marked; everything else degrades gracefully.

Defaults

Applied to every run unless the programme overrides them.

API keys

Optional. Each source is skipped cleanly when its key is absent, so the framework works with none of these configured — they simply widen what passive enumeration can see. Keys are written to your local config file and never sent back to this page.

Update

Pulls the latest code from GitHub. Your engagement database and configuration live outside the checkout and are never touched by an update.
